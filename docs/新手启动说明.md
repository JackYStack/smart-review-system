# 新手启动说明

## 先理解这套系统

这不是一个单独的网页文件，而是多个服务组成的平台：

- `frontend`：浏览器中看到的页面；
- `backend`：登录、模板、任务、规则、报告等 API；
- `worker`：在后台执行耗时的方案审查；
- `mysql`：保存用户、规则、任务和审查结果；
- `minio`：保存上传的 Word 与导出的报告；
- `onlyoffice`：在线预览和人工审阅 Word；
- `paddleocr`：把方案页面识别为标题、正文、表格和公式；
- `Dify/LLM`：知识库检索和大模型语义审查，按团队实际地址配置。

因此，只启动前端只能看到登录页，不能完成真实审查。

## 第一次启动

1. 在部署电脑上安装并启动 Docker Desktop；
2. 把根目录 `.env.docker.example` 复制为 `.env.docker`；
3. 在 `.env.docker` 中修改 `HOST_IP`、三个密码/密钥和管理员信息；
4. 首次启动时设置 `ADMIN_BOOTSTRAP=true`，填写 `ADMIN_USERNAME`、`ADMIN_PASSWORD` 和 `ADMIN_PHONE`；
5. 在项目根目录执行：

```powershell
docker compose --env-file .env.docker -f docker-compose.yml -f docker-compose.paddle.yml up -d --build
```

6. 首次启动 PaddleOCR 会下载模型，需要耐心等待；
7. 浏览器打开 `http://HOST_IP`；
8. 管理员创建成功后把 `ADMIN_BOOTSTRAP` 改回 `false`，再重启服务。

## 登录后配置顺序

1. 在“系统设置”连接团队的 Dify 知识库和大模型；
2. 新建危大工程方案类型，例如深基坑、模板工程、脚手架、起重吊装；
3. 维护每类方案的编制依据；
4. 上传对应 Word 模板，系统会用 PaddleOCR 生成标题树；
5. 按章节配置审查提示词、知识库、上下文一致性和工作流；
6. 上传测试专项方案，查看结构审查、智能审查、日志和批注报告；
7. 对已知缺陷样本逐条核对，不能只看页面是否出现“审核完成”。

## 常用检查命令

```powershell
docker compose --env-file .env.docker -f docker-compose.yml -f docker-compose.paddle.yml ps
docker compose --env-file .env.docker -f docker-compose.yml -f docker-compose.paddle.yml logs -f worker
docker compose --env-file .env.docker -f docker-compose.yml -f docker-compose.paddle.yml logs -f paddleocr
```

停止系统：

```powershell
docker compose --env-file .env.docker -f docker-compose.yml -f docker-compose.paddle.yml down
```

`down` 只停止并移除容器；数据库、文件和 Paddle 模型仍保存在 Docker 卷中。不要随意增加 `-v` 参数，否则会删除这些数据。
